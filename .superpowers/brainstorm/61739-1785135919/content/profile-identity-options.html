Chromium Profile Identification

Goal: make each running profile recognizable both in the window itself and at the system icon level.

Recommended

A. In-window identity + generated launcher apps

Use a lightweight in-window marker for every profile, then generate per-profile app wrappers/shortcuts for Dock or taskbar identity.

Pros

  • Works even when multiple browser windows are already open.
  • Gives both immediate visual recognition and system-level grouping.
  • Lets Facade own the identity model instead of depending on Chromium UI.

Cons

  • Needs separate implementation paths for macOS and Windows launcher behavior.
  • Wrapper apps/shortcuts add lifecycle complexity.

B. Chromium-native hints only

Try to lean on Chromium profile theme color, title text, and platform-native profile shortcuts as much as possible.

Pros

  • Lower implementation cost.
  • Less custom OS integration code.

Cons

  • Inconsistent across platforms.
  • Facade has less control over final appearance.
  • May still fail to distinguish windows clearly enough.

C. Facade overlay experience

Add a Facade-owned injected visual layer inside browser windows and treat Dock/taskbar identity as secondary.

Pros

  • Most visible and customizable in-window cue.
  • Can show color, name, tags, and runtime state.

Cons

  • Higher risk of interfering with page rendering or automation.
  • Still needs a second strategy for Dock/taskbar identity.
